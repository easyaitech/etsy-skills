# Etsy 产品定义

把已有商品变成有明确购买理由的产品，输出供 `etsy-listing-builder` 和 `etsy-listing-images` 共用的产品定义。中文讨论；面向买家的品类名称与表达按目标市场语言拟定，默认英文。重点是定位与取舍，不是提前写满上架字段或生成图片。

默认从已有实物出发，尊重用户已选产品与经营边界。参考讨论提供线索，不是既定答案；依据商品与证据选择方法，不强制情感故事、礼赠定位、系列化或固定数量的方案。

调研是可选步骤，不是产品定义或下游执行的前置门槛。先按第 1 节确认本轮调研选择；用户已明确选择时直接沿用，不重复询问。

- **不需要调研**：跳过第 2 节，基于商品事实、用户已定方向与现有资料进入第 3 节，不生成调研任务书或验收报告，不等待市场数据。
- **需要调研**：只研究用户选择的问题，可仅查大类高搜索词及本品可承接的关键词，也可研究定位、竞品或定价；不自动扩展成全套研究。按第 2 节先交需求、再验收回传。已有资料先复用；已提供调研包时直接按所选范围验收，不补写任务书或要求重做。

产品定义的完成条件：商品身份、核心购买理由、表达要求与经营决定清楚，事实、用户选择、建议和市场证据分开，关键未知项明确，用户确认后交接下游。跳过调研或限定研究范围时，不因缺少市场证据阻断定义，也不把用户判断包装成市场验证。

## 报告交付格式

面向用户的调研需求、调研验收、补充研究与最终产品定义报告默认以 HTML 为表达载体；报告制作及验收读取 [HTML 报告交付](references/html-report.md)。最终内容直接在 HTML 内完整呈现，不能仅做摘要或指向 Markdown 的链接页。Markdown 为同版本源稿与技能交接资料，CSV 等原始证据可作为附件。用户另行指定格式时依其要求。

## 1. 弄清实物与决策问题

先读用户资料、照片、既有 Listing 和确认记录。若本轮尚未明确调研选择，先问：“这次需要调研吗？可以不调研，直接按你的想法做产品定义；也可以只查大流量关键词，或调研你关心的其他问题。”等待回答期间可整理商品事实，不自行启动研究或把未回答视为同意。用户已说“不调研”“直接做”或“只查关键词”时，按该范围继续。只问会改变定位的缺口，少量分轮提问；商品事实不知道就列未知；市场问题在用户选择调研时转成任务，否则标为未知或待试假设，不要求用户凭印象回答。

识别实际出售物与包含物、材料工艺、尺寸及用途、可交付的定制范围、价格成本约束、制作配送能力、目标市场、用户想保留的方向。目标市场不能从语言或文化题材推断。照片不能证明材料成分、产地或未展示的工艺。

把“现在能交付”“尚需打样/验证”“仅为创意”分开。可提出提高价值的产品调整，但以可选建议呈现；新增包装、套装、用途或复杂定制在落实前不进入现售承诺。

先明确本轮要决定的问题，例如“这件雕刻品优先卖给谁，强调什么价值”。定位明确且只需局部改稿时，直接交相应下游技能，不把全套调研设为所有 Etsy 工作的前置门槛。

## 2. 可选调研：先交需求，再验收回传

仅在用户选择调研时执行。记录本轮研究问题和排除范围；只查关键词时，只交关键词需求与对应验收，不要求购买动机、定价或完整竞品研究。关键词相关性可通过实际搜索结果核对。用户已有的价格、定位和图片方向作为经营选择沿用，除非用户要求检验，不将它们设为待推翻的研究假设。用户可随时取消或缩小调研范围，取消后直接进入第 3 节。

编写首份产出时读 [调研任务书](references/research-brief.md)，根据当前产品填写独立可转交的 `research-brief.html` 及同内容 Markdown 源稿。先沿用已知实物、市场和能力，未知项单列；除非连商品或市场范围都无法界定，不为等待成品图或全部经营资料阻塞任务书。

任务书按约定范围从以下问题中选取：“哪些需求确实存在、上位大类有哪些高搜索词、本品能承接其中哪些需求、买家在比较谁、为什么买、价格与配置如何、什么试售价有依据、我们能兑现什么差异”。涉及关键词时，按调研任务书中的“大类发现与机会筛选”向上探索，再回到具体意图，分别交付大类高搜索词榜与本品关键词机会表；不能只围绕材料词和已知用途找长尾词。完整定位研究同时覆盖关键词数据、竞品实际商品与买家反馈；专项研究只覆盖约定问题，不能把关键词表当作完整市场研究。种子词是检索起点，不是推荐标题或已验证需求。提供可调采样规模和预算优先顺序，允许研究者按实际结果扩展或报告找不到，不强行凑数。

将任务书交用户转交执行，明确当前状态为“等待调研回传”。不把零散网页、生成式摘要或个人审美当成市场结论。用户可以依据自己的经营判断选择方向，明确其依据即可。用户明确授权本代理执行调研时，先出需求再执行，不自动派发或联系其他机器人。

收到数据后读 [调研与判断](references/research.md)，核对原始记录、市场/时期/指标口径、竞品覆盖、买家证据与反例。输出 `research-assessment.html` 并同步保存 Markdown 源稿，逐个决策问题标明可回答、仅弱信号、无法回答及证据编号。只验收约定问题；范围外的缺口不列为未通过。资料不足时说明哪些市场结论不能成立，提出最小补充选项，由用户选择补研或带着未知项继续定义，不强制补研。已有可比价格线索、仅成本或成交验证未完备时，按定价参考给条件化建议。已足够的部分保留，不重做全套研究。不能用用户确认代替证据检查，但证据不足不妨碍用户作出经营选择。

## 3. 做出定位取舍

基于商品事实、用户已确定的选择与现有证据做定义；跳过调研时直接执行本节。尊重用户的定位、售价及图片方向，不要求用调研重新证明。通常需要连通以下问题：

- **购买情境**：谁买、谁使用或收礼、什么触发购买、希望获得什么结果。用行为与场景解释人群，年龄性别只有影响决策时才使用。
- **替代选择**：买家还会买什么或干脆不买，当前商品在哪些方面更适合、在哪些方面不占优势。同行共有特点可以是必要卖点，但不能冒称独有。
- **价值与证据**：把真实特点连到具体收益。价值可来自实用、审美、身份表达、情感或其他原因；不把每件商品都解释成礼物或纪念品。核心购买理由优先清楚，其他卖点作支撑。
- **交付可行性**：主张能否通过成品、工艺、服务或使用体验兑现；成本、定制复杂度、时效和素材是否支持。故事不能补偿无法兑现的体验。

每个核心决定注明依据是商品事实、用户选择、策略建议还是市场证据；使用研究结论时引用对应证据编号。没有市场证据时，可以提出并确认待试的定位，但不能宣称该方向已获市场验证或需求优于其他方向。方向有实质分歧时，比较少量候选的需求证据、商品匹配、差异、履约负担与未知项，给出推荐及理由；方向清楚时直接给单一推荐。没有数据不编造市场规模、销量、转化率或精确评分。

对当前 Listing 选定一个优先购买情境和清晰主张，说明暂不主打的方向及原因。产品家族可以有更宽的统一定位，但不把所有人群、节日和用途塞进一条 Listing。只有搜索意图、实际配置或展示证据确有差异时才建议拆分页面，不自动扩展成全系列开发任务。

优先沿用用户已定售价，记录币种、配置、包含内容及确认状态，不要求竞品调研为其背书。用户需要定价建议时，按已有成本与资料提供条件化建议；只有用户选择定价调研时才采集竞品价格。涉及定价分析时读取 [竞品定价与试售建议](references/pricing.md)。尚未定价可标为待用户决定，继续其他定义工作；不得编造售价或把试售价包装成市场成交结论。

## 4. 把定位变成表达要求

为核心价值建立对应关系：**买家要什么 → 商品如何满足 → 有什么证据 → 文案如何说 → 图片如何展示**。没有证据的承诺标为待验证或改成真实可支持的表达。

区分内部定位、买家能理解的商品名称与搜索入口。材料专名和品牌故事可提供识别度，但不能替代“买到什么”的清楚说明。选择关键词调研时，先发现更大的需求，再检查商品能否满足；可提出新增方向供用户选择，不自动推翻已定定位。跳过调研时，依据商品与用户方向整理相关搜索表达，标为“热度未验证”，不要求补大词榜。高搜索量是进入比较的理由，不是预计可获得的流量或成交量；相关的大词即使竞争高也保留，并寻找本品能兑现的细分切入方式。

给语气、信息主次和少量示范表达。视觉部分明确图片需要表达的核心价值、必须证明的事实、买家疑问、素材缺口与真实性边界；不锁定张数、图序、构图或逐图文案，这些由图片技能依据真实素材决定。情感价值落到具体使用、关系和商品细节；文化背景与现代品牌寓意分开，象征意义不能变成历史事实、功效或耐用保证。材质、工艺、包装与包含物以事实为准。

## 5. 形成定义并由用户确认

出稿时读 [产品定义与交接](references/handoff.md)，以 `product-definition.html` 交付完整最终报告，同步保存 `product-definition.md` 供下游读取。展示推荐定位、选择理由、舍弃方向、证据强弱和落地限制；需要改动实物的建议单列。

请用户确认具体版本及主攻方向。已明确确认的决定沿用，不重复审批。未决项只有会改变定位、商品身份或核心承诺时才阻断对应部分；非关键缺口不妨碍交接已确认范围。已完成研究仍有剩余不确定性时如实保留；用户确认不等于市场验证。选择调研时仍须如实检查已用资料；跳过调研时不要求补验收报告。

## 6. 自动衔接执行

默认用户确认产品定义后，在同一任务中先读取并执行 [Etsy 图片](../etsy-listing-images/SKILL.md)，携带同一版本定义及原始素材。图片技能确定数量、顺序和具体设计，遵守策划确认、主图确认和后续制作验收流程。产品定义确认不能代替具体图片方案确认。

最终图库完成验收及适用的用户确认后，再读取并执行 [Etsy 信息生成](../etsy-listing-builder/SKILL.md)，基于实际图片生成含逐图 ALT 的最终 HTML 上架填写稿，核对图序、名称、选项、包含物与承诺。图片未完成时可收集经营字段和保存资料，但默认不提前交付上架填写稿；用户明确要求预稿时标为预稿，不能用图片计划冒充实际图库或编写最终 ALT。

缺素材时继续不依赖它的图片策划与事实整理，说明缺口，不越过依赖制作最终填写稿。用户只要定义或另行指定范围/顺序时依其要求。衔接技能不意味着创建聊天、派发子代理或发布商品。

下游负责字段、关键词细化、图序和执行规格，保持已确认定位。新证据若推翻关键决策，指出冲突、建议修订定义并确认受影响部分，避免两份交付物各自重新定义产品。仅改变措辞或构图无需重开定位讨论。
