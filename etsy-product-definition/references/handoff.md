# 产品定义与交接

## 单一产品定义

用户跳过调研，或所选调研已完成验收、或用户选择保留研究缺口继续时，在该产品交付目录生成完整 `product-definition.html` 报告，保存同版本 `product-definition.md` 供下游读取；按 [HTML 报告交付](html-report.md) 验收，按决策需要组织，不为填模板重复内容。保持以下信息可找到：

1. **身份与状态**：产品标识、版本/日期、目标市场、讨论范围及调研选择（跳过/仅关键词/其他约定范围）；草稿/待确认/已确认；确认了哪些决定，哪些仍未验证。
2. **事实边界**：出售物与包含物、规格变体、材料/工艺/产地、定制交付能力、素材角色和来源。未知值明确标注；产品调整建议单列。
3. **定位结论**：优先买家、使用者/受赠者、触发场景、核心价值、替代选择、选择理由、暂不主打方向。家族与当前 Listing 定位需要时分开。
4. **证据与取舍**：已调研时引用实际存在的任务书、回传文件与验收报告，研究结论对应证据编号；未调研时记录商品事实、用户选择和策略假设，不要求创建调研文件；重要来源及日期、观察与推断、反面证据、候选为何保留或舍弃。用户选择可决定策略，不能升级为市场事实。
5. **搜索机会与表达映射**：已做关键词调研时引用大类高搜索词榜与承接机会表，说明需求入口、证据与取舍；未做时只整理相关表达，注明热度未验证，不强制提供榜单；区分现有可承接与需调整。卖点对应买家收益、事实支撑、文字表达和视觉证据、限制或禁用承诺，标明主次。视觉要求写清需要表达/证明什么、素材缺口和真实性边界；图片数量、图序与具体设计留给图片技能。
6. **经营与验证**：记录用户已定售价或待定状态及包含内容/运费/税口径；用户需要价格分析时，按 [定价参考](pricing.md) 提供已有资料支持的建议、成本情景及调价条件，不强制竞品对照；落地限制、可选调整、关键假设与验证行动。
7. **执行交接**：两项下游任务范围、已确定与待补内容、文件路径、当前完成状态。

可用自然语言说明核心决定：“为正在寻找……的买家，这是一件……，帮助其……；选择它的理由是……，证据是……。”这不是必须套用的口号。

## 两个下游分别接什么

| 下游 | 从定义继承 | 下游补全 |
| --- | --- | --- |
| etsy-listing-builder | 优先买家与场景、核心主张、卖点次序、事实承诺边界、买家语言和搜索意图、已确认配置、售价建议与确认状态及运费口径 | 最终图库就绪后核验关键词、补全 Etsy 字段、英文成稿与变体映射，逐图查看并生成 ALT 和最终 HTML |
| etsy-listing-images | 目标市场、商品身份与包含物、购买理由及视觉证据、语气与情境、素材来源缺口 | 数量、顺序、具体构图与英文标注、素材资格、策划及主图确认、生成和验收 |

两个技能记录所用定义路径与版本；HTML 与 Markdown 同步生成，确认针对同一版本，修改时一并更新。`listing-data.json` 继续作为上架字段资料源，记录定位出处，不另造相互竞争的定位；图片计划记录同一引用。下游继承调研选择和用户已定售价、图片方向，不得以补字段为由重新启动已跳过的研究。关键词仍可按商品事实细化，不能宣称未经验证的热度。

接续其他聊天时提供文件路径、对应 Listing/变体及确认范围。旧版本保持可追溯；修改定位后列出受影响的文案图片，不把旧文件默认为已同步。默认顺序为产品定义确认 → 图片策划/制作/验收与适用确认 → 最终上架填写稿。图片交接清单携带最终顺序、文件路径、实际规格、素材角色与状态；上架技能逐图查看后生成 ALT。若更换已交付图片，同步更新对应缩略图、文件引用、ALT及相关文案。

## 参考案例的边界

用户提供的梅子青讨论展示了从材料与定制特点推导私人意义、再映射到人群与表达的一种方法。可借鉴事实—收益—意义的连接、统一定位与搜索入口分离，以及概念经履约验证后才能成为承诺。

案例不证明纪念品一定优于首饰定位，也不证明情侣、宠物等方向的优先级；美国市场、六个系列、三级定制、礼盒与情感口号都不是通用默认。材料产地、文化背景、趋势统计和手工方式在具体任务中分别核实。

例如，互相呼应的雕刻可能支撑关系表达，但两块石头本身不证明配对体验已成立。应检查实际设计、包含物与交付，再确定表达。实用性更重要的商品则优先解释使用收益和性能证据。
