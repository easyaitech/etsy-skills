# `Inventory 库存品` / `Inventory Ledger 库存流水` 表 Schema

> **这两张表由后端 provision 自动创建与维护，不要手工建、不要改列名。**
> 老租户没有这两张表时，请管理员跑一次库存表开通（后端 `POST /api/admin/accessory-provision`，
> 幂等：缺表建表、旧名改新名、缺列补列，永不写行）。手工建的表列名对不上，订单自动扣减会静默失效。
>
> 逻辑键：`Inventory 库存品` = `accessories`，`Inventory Ledger 库存流水` = `accessory_ledger`。
> 历史名（v0.6.37.0 短暂使用，已由 provision 自动改名）：`Accessories 包材附件` / `Accessory Ledger 包材流水`，
> 旧列名 `附件名称` 已改为 `库存品名称`（读取端仍兼容旧列名，写入一律用新列名）。

---

## 边界：这两张表 vs `Products 商品` 表的「库存」列

| | `Inventory 库存品` 的 `当前库存` | `Products 商品` 的 `库存` |
|---|---|---|
| 含义 | 仓库里**实际还剩几个**（成品 + 包材） | Etsy **平台在售**挂牌数量 |
| 谁维护 | 本系统：流水求和派生 | listing 读取自动回写（平台为准） |
| 身份键 | `库存品名称`（成品 = 真实 SKU） | 商品表 `SKU`（店内前端标识） |
| 谁该读它 | "还剩几个 / 够不够发 / 该补货吗" | "平台上挂着几件 / 是不是售罄了" |

店主问实物库存时**只能读本表**。商品表的 `SKU` 只是前端展示与绑定标识，不代表真实库存单位；
两张表的数字对不上是正常的（平台挂 10 件、仓库有 3 个成品完全可能），**不要试图对齐它们**。

## `Inventory 库存品` 表

一行 = 一个库存单位。成品（真实 SKU）与包材附件同表管理。

### 字段

| 字段名 | 类型 | 说明 |
|---|---|---|
| `库存品名称` | 单行文本 | **唯一键**。成品填真实 SKU（`SCROLL-24x36`），包材填名称（`麻布袋-小号`）。流水表按这个名字记账，改名前必须把流水表里的旧名一并改掉，否则历史流水成为孤儿 |
| `类型` | 单选 | `成品` / `包材` / `赠品` / `其他`。仅用于筛选查看，不影响扣减与提醒 |
| `当前库存` | 数字 | **服务端专列，禁止写入**。= 库存流水表该库存品所有 `变动数量` 之和；工具写流水后当场重算，店主直接手改表时需调用 `/api/hermes/inventory/recalc`。报实时数以 recalc 返回值为准 |
| `安全库存` | 数字 | 跌到这个数（含）早报点名提醒补货。留空 = 不提醒 |
| `单位` | 单行文本 | 个 / 只 / 张…… 只影响提醒文案 |
| `适用品类` | 单行文本 | 绑定规则（通配）：命中 `Products 商品` 表「品类」列的商品每卖一件自动扣 1。多值用逗号 / 顿号分隔。适合整类共用的包材 |
| `适用商品 SKU` | 单行文本 | 绑定规则（点名）：填商品表 `SKU` 或 `平台商品 ID`（两个键都认），多值用逗号分隔。适合一品一库存的成品 |
| `颜色/变体` | 单行文本 | 可选。按颜色分库存时照抄 listing 颜色选项原文；同一 SKU 每个颜色一行。留空 = 不按颜色拆分 |
| `采购链接` | 链接 | 补货采购 / 补做链接，补货提醒时直接带出 |
| `备注` | 多行文本 | 自由记录 |

### 绑定语义

- 两列可以同时填，**命中任意一条即扣**。
- `适用品类` 的值必须与商品表「品类」列里实际出现的词一字不差（品类词对不上就永远扣不到）。
- 一个商品可以同时命中多个库存品（典型：卷轴成品 + 麻布袋 + 小礼品），每个各扣各的。
- 同一订单里同一库存品被多件商品命中时，数量累加成**一条**流水（幂等键 `订单号:库存品名称` 保证一单一品只有一行）。
- 按颜色管理时，颜色必须与 listing 选项原文一致；同一商品多色且颜色数与购买件数一致、每个颜色都匹配时，按每件对应颜色扣减。颜色缺失、无匹配或件数与颜色数不符时，整件不自动扣并点名，不能猜测归色。

## `Inventory Ledger 库存流水` 表

一行 = 一次库存变动。**只追加，不修改**——记错了记一条冲正行，不要改旧行。

### 字段

| 字段名 | 类型 | 说明 |
|---|---|---|
| `库存品名称` | 单行文本 | 与库存品表 `库存品名称` 一字不差才算同一个库存品 |
| `变动数量` | 数字 | 入库为正（`+100`）、扣减为负（`-2`）、盘点按差额（可正可负）。**当前库存 = 本表该库存品所有行之和** |
| `类型` | 单选 | `销售扣减`（**系统专用**，人工不得填）/ `采购入库` / `盘点调整` / `其他` |
| `关联订单号` | 单行文本 | 销售扣减的来源订单号，系统自动写；人工记账留空 |
| `流水 ID` | 单行文本 | **服务端专列，禁止写入**。系统幂等键（`订单号:库存品名称`），防同一单重复扣。人工记账留空 |
| `发生时间` | 日期 | 留空或传毫秒时间戳；**绝不要填日期文本**（日期列收到文本会导致整行写入被拒） |
| `备注` | 多行文本 | 写清缘由。系统自动扣减时这里是命中的商品标题 |

### 类型语义

| 类型 | 谁写 | 典型场景 |
|---|---|---|
| `销售扣减` | **系统自动** | 新订单首次入库时按绑定规则写负数行；同一单幂等，绝不重复扣 |
| `采购入库` | 人工 / agent 代录 | 到货、补货、期初建账 |
| `盘点调整` | 人工 / agent 代录 | 实盘与账面对不上时补差额（记差额不是结果值） |
| `其他` | 人工 / agent 代录 | 损耗、样品送出、退货回冲等 |

## 服务端专列（通用写工具一律拒收）

| 列 | 所在表 | 拒收原因 |
|---|---|---|
| `当前库存` | `Inventory 库存品` | 派生值，由流水求和回写；手改下轮就被覆盖，还会在窗口期误导补货判断 |
| `流水 ID` | `Inventory Ledger 库存流水` | 自动扣减幂等键；允许伪造就能让真实订单的扣减被「已存在」静默跳过 |

写这两列会返回 `BITABLE_FIELD_SERVER_GENERATED`。**这是设计行为，不是后端故障**，不要重试、不要换写法绕，改用流水记账。

## 自动扣减链路（了解即可，不需要 agent 介入）

1. 插件巡检抓到新订单 → 后端订单入库（`Orders 订单` 表首次建行）
2. 后端解析订单行的商品标题 → 匹配 `Products 商品` 表 → 得到该商品的 `品类` / `SKU` / `平台商品 ID`
3. 按绑定规则（`适用品类` 通配 + `适用商品 SKU` 点名）找出命中的库存品
4. 每个命中的库存品写一条负数 `销售扣减` 流水（幂等键 `订单号:库存品名称`）
5. 重算 `当前库存` 快照并回写；跌破 `安全库存` 的进入早报补货提醒

**匹配不到商品的订单行不会静默漏扣**：后端会在新订单播报里点名"这些商品在商品表里没找到，库存没扣"，
店主看到后需要人工在流水表补记。收到这类反馈时，先帮店主核对商品表「标题」列是否与 Etsy 上一致。

## 录入约定

1. 新建库存品后**必须单独记一条期初流水**，否则它的当前库存是 0。
2. 盘点记差额、不记结果值：账面 25、实盘 30 → 记 `+5`，备注写"盘点：实际 30"。
3. 记错了记冲正行，不改旧行、不删行——保留完整轨迹比清爽更有价值。
4. 退款 / 取消订单不会自动回冲，需要人工记一条正数流水（类型 `其他`，备注写明订单号）。
5. 库存品名称一旦被流水引用就尽量别改；确需改名，库存品表和流水表两边必须同时改。

## 建表后的下一步

1. 把主要包材和常备成品各建一行，填好 `安全库存` 和绑定列。
2. 实盘一次，给每个库存品记一条期初 `采购入库` 流水。
3. 下一笔真实订单进来时，去流水表确认自动扣减是否按预期发生（有没有出现该扣没扣、或商品没匹配上）。
