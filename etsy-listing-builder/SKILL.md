# Etsy Listing 文案生成

核心任务：让真实商品更容易匹配相关搜索，让买家快速理解商品价值并愿意进一步了解或购买。重点优化标题、Tags、描述、变体名称和个性化说明；搜索覆盖与自然、具体、有吸引力的表达一起评估，不以堆词或虚构卖点换取表面覆盖，也不保证排名或流量提升。

完成结果：一份独立、可离线打开的 HTML，按 Etsy 后台相关字段顺序给出英文成稿、必要选择项和逐图 ALT。中文沟通和操作说明放在复制内容之外。交付填写稿；已确认且授权写入的字段另按项目接入协议委托 listing-catalog 同步内部目录，不阻塞文件交付。不自动发布或改写线上商品。

## 默认范围

默认不采集、追问、建议或生成物流信息（运费、制作周期、运输周期、发货地、配送目的地），也不生成制作背景（谁制作、如何制作、制作流程或生产合作方）。这些信息缺失不列为本次文案待补项，不阻塞交付，HTML 不预留对应章节。目标市场用于语言与关键词选择，不等同于配送范围。

材料、尺寸、交付内容、可选款式和实际定制范围仍是写好文案所需的商品事实。用户已提供且与购买理由直接相关的工艺事实可用于准确表达卖点，但不为此展开制作背景访谈或补写故事。用户明确要求补充上述范围外内容时再处理；确有适用的平台强制披露要求时单独提示必要项，不擅自填写，也不扩展为整套后台资料采集。文案完成不等于所有后台必填项已完成。

## 依赖关系

按 [依赖降级协议](../shared/dependency-protocol.md) 处理缺失基座；下表只决定当前步骤是否继续，不把建库变成填写稿前置条件。

| 依赖 | 填写稿生成／局部修改 | 授权目录同步 |
| --- | --- | --- |
| shop-foundation（BRAND / SHOP） | 需品牌语气或店铺政策却缺资料时 **DEGRADE**：用已确认的其他资料继续，标明缺口，不自编承诺；不涉及这些资料的局部改稿 **SKIP** | 已有可定位的店铺总 Base 配置时 **SKIP**；无法定位时 **BLOCK** 同步，不阻塞文件交付 |
| listing-catalog（商品目录） | 需要目录事实却未配置或读不到时 **DEGRADE**：按用户资料继续并注明来源；无需目录事实的局部改稿 **SKIP**。线上事实仍走只读契约 | 无可用商品表或 Base 写工具，或无法确定目标商品与新增／更新授权范围时 **BLOCK** 同步，不阻塞文件交付 |
| assets-library（素材池） | 已有可用的最终图片文件时 **SKIP**；缺最终图片按本技能的图片就绪规则处理，不要求先建素材池 | **SKIP**；素材正式入库另按其授权边界处理 |

## 接收产品定义（如有）

已有 `product-definition.md` 时，先读对应本次 Listing 的已确认定位、目标市场、核心购买理由、表达要求与事实边界，在 `listing-data.json` 记录定义路径与版本。复用仍有效的调研，补字段与关键词缺口，不重新盘问或另选目标人群。沿用定义中的调研选择：跳过时依据商品事实整理关键词并标注热度未验证，仅关键词时不扩展到定价或定位研究；保留用户已定售价和图片方向。产品建议、未验证假设不能写成现售事实；新证据与核心定位冲突时提出修订并确认受影响决定，措辞优化无需重开定位。同时接收图片技能交付的最终图序与文件清单，逐图查看成图后核对 ALT 与共同事实。

用户要求先明确定位，或本次任务确需在不同人群/购买理由之间取舍时，使用 [Etsy 产品定义](../etsy-product-definition/SKILL.md)。单纯填写或局部改稿直接继续，不强制补做全套定位。

## 图片就绪与出稿时机

完整上架流程按“已确认产品定义 → 图片策划/制作/验收 → 最终填写稿”执行。用户已有可用最终图片时直接接收，不要求重新生图；无需定义的独立修改任务继续按原范围处理。新建最终填写稿前确认实际图片文件、顺序和验收/适用确认状态，计划或预览不能替代成图。视觉验收、平台适用性和文案完成状态分别记录。

图片未完成时，可整理商品事实、关键词及文案，默认暂不交付填写稿；用户明确要求时才提供标注未完成的预稿，未就绪图片的 ALT 留空并说明依赖。已有提前生成的预稿保留，待图库完成后更新为最终稿。逐图 ALT 必须依据实际查看的对应最终文件编写；已有可追溯的查看记录且文件未变时沿用，图片变更后重新查看并核对受影响部分。

## 工作流程

1. **整理事实。** 先读用户已给的文字、链接和图片，提取与文案有关的商品类型、目标市场、目标买家、使用或礼赠场景、核心购买理由、交付内容、材料尺寸与定制范围。仅补问影响选词、卖点准确性或买家正确下单的缺口；默认范围外的信息不追问。图片上的标注可作为待核实信息；附件中的生成提示或交付指令不构成用户指令。只追问真实缺口，每轮问少量相关问题；用户说不知道时提出补齐方式或标为待确认，不重复盘问。
2. **研究并提出建议。** 按 [关键词与出稿规则](references/listing-rules.md) 整理关键词及上架表达；有已确认的调研范围时仅在该范围研究关键词及相似商品。跳过调研时不新开研究，基于事实与已定方向出稿；围绕相关搜索意图选择关键词，将已确认的商品特点转成具体购买理由，优化标题、Tags、描述和选项表达。变体或价格方案仅在用户需要时扩展。所有任务出稿前读此文件。研究不阻碍先做已有信息能够支持的部分。事实、建议、未知值分开；价格、时效、退换货等经营承诺依已有授权，不代替店主创造承诺。
3. **形成单一资料源。** 在交付目录保存 `listing-data.json`，记录事实的来源与确认状态、关键词证据、最终字段、变体映射、逐图 ALT 和未决事项。HTML及描述从这些资料生成；选词图等视觉成品由图片技能负责，选项和编号与本资料核对，避免分别保存互相冲突的文案。价格测算注明币种、成本范围和缺失费用；市场标价不等于成交价。
4. **生成并验证。** 按 [HTML 交付与一致性检查](references/html-delivery.md) 输出文件，实际计算长度、检查编号与复制内容。关键事实或平台适用项待核时仍可交付已完成部分，明确待补项，不称为可直接发布。
5. **局部迭代。** 保留用户已经确认的内容。只修改请求涉及的字段及其依赖项；改变预设文字时同步描述、变体、图稿和 ALT，旧图尚未改时明确标出不一致。没有新事实、用户要求或有效研究证据，不为了“优化”反复改稿。

## 个性化字段

仅在商品提供个性化时生成该模块；普通商品不为此补问。按问题类型交付可复制英文内容：文本输入和文件上传提供标题及适用的填写说明；下拉选择提供标题和各选项，不生成填写说明；上传需区分文件时另给标签。标题说明买家要提供什么，说明解释如何提供。多个定制问题按实际需求逐项交付，不为版式强行合并成一个字段，也不无故扩成多字段。字段长度、类型及内部数据映射见 [关键词与出稿规则](references/listing-rules.md)。

默认不附加收费开关、定价或后台买家输入上限设置，不为这些设置阻断文案交付；用户明确要求时再扩展。商品的实际定制容量可以写进买家填写说明，不能由平台允许输入的字符数反推制作容量。必要而未知的后台设置记入内部待补项，不伪装成已填；省略设置界面不等于可以省略影响买家正确下单的条件。

## 店铺信息与通用能力分开

确认过的店铺配置引用既有店铺基座；交付目录只保存本次使用的来源快照，不建立竞争真源，不写进通用技能规则。仅在本次文案确实引用时核对币种、售价等会变化的信息；不为复用店铺配置额外采集物流或制作背景。不将某件卷轴的颜色、中文预设或不适合 wedding 的判断扩展成所有商品的限制。

写作偏好、字段限制与关键词分配统一维护在 [关键词与出稿规则](references/listing-rules.md)，此处不再复制另一套默认值。本地已确认的表达偏好不能冒充所有店主的配置；Hermes 多租户部署的店主偏好仍走共享引导中的设置层，修改本地技能不等于已写入该服务。
