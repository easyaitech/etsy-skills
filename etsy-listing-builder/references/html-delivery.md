# HTML 交付与一致性检查

## 页面与复制

独立 HTML，内置样式和复制交互，不依赖在线字体或外部脚本。图片尽可能嵌入，或交付完整资源目录；不要让文件依赖易失的临时路径。转义所有用户提供的文本，作为文本展示而非可执行 HTML。

页面和左侧导航默认按用户提供的后台顺序：图片与视频 → 分类 → 标题 → 描述 → 变体 → 材料 → Tags → 尺寸 → 价格 → 物流 → 其他选项；研究依据放最后并可折叠。后台实际顺序变化时随之调整。

- 每个文本字段独立复制，复制内容不含中文说明、字段名称、来源或统计。反馈成功必须来自实际复制成功；失败时允许手动选择复制。
- 个性化模块分别展示“标题”和“描述”，各有独立复制按钮；不附加收费开关、加价方案或字数限制设置栏。资料源使用 personalization.title 与 personalization.description；已知容量等事实可以留存，不能自动渲染为额外设置。
- Tags 只展示一条半角逗号连接的完整内容和一个复制按钮，不展示单标签卡片。
- 图片按序列出缩略图、文件名、英文 ALT、字符数与复制按钮；有替代版本说明二选一，避免重复上传。
- 选择项给出实际可选值或核对指引；没有证据时不编分类路径、运费模板或生产合作方。
- 尺寸优先采用目标市场常用单位，并保留原单位；数值可单独复制，旁边清楚标单位。区分商品整体、书写区域和物流包装尺寸，换算后标近似值。
- 已确认、建议待确认、缺失字段可辨识。待填占位符不混入可直接复制的正式文案。

## 单一资料源

`listing-data.json` 至少包含：商品与店铺身份、市场语言币种、事实与来源/确认状态、关键词证据、标题/描述/tags、图片文件与 ALT、变体及中文编号映射、尺寸和换算、价格/库存、物流政策、未决项。

字段修改时先更新该资料，再生成 HTML、图稿和描述。不是重用 FuBlessings 这件卷轴的固定事实或选项。输出路径稳定，保存后检查文件存在；已存在的用户内容保留，不能用早期生成脚本覆盖后续修改。

最终稿的图片、缩略图和 ALT 必须对应实际已验收的同一组文件及版本；收集最终清单后逐图查看，不根据策划表推测画面。图片缺失时不标为最终稿。更换图片后同步更新缩略图、文件引用和相应 ALT。

## 完成检查

机械检查可用短脚本，避免让模型凭目测数长度：
- 个性化标题 ≤45 字符、Instruction（`personalization.description`）≤120 字符，含空格、标点与换行；以实际复制内容计数并展示当前字符数／上限，超限改写后重新验证。不要与买家输入限制或雕刻容量混淆。
- 标题 ≤140；tags 13 项且每项 ≤20；所有变体按本次确认的上限计算，含编号/空格；ALT 按所选规范检查。
- 完全重复与近似重复分别检查，重复提示不等于强制删除自然词组。
- 图序、文件、ALT 一一对应；编号、中文、英文含义、价格在图稿、描述、变体间一致。旧图没更新则标为待替换，不能谎报完成。
- 单位换算、币种、制作起算点、确认等待与总时效一致。缺费用不报净利润；未确认库存不编数量。
- 所有复制按钮指向唯一有效字段；链接与资源可用。可用浏览器时检查桌面/窄屏排版、实际复制内容；未实际验证的能力如实说明。
- 没有新要求或新证据时沿用已确认字段。与现有同店商品作语义对比，而非为了不同强行更换准确品类词。

交付时提供 HTML 链接，简要列出真实待补项。只有影响最终使用的缺口才追问；不以“再确认一次”阻止已经授权的修改。
