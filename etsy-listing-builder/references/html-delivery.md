# HTML 交付与一致性检查

## 页面与复制

独立 HTML，内置样式和复制交互，不依赖在线字体或外部脚本。图片尽可能嵌入，或交付完整资源目录；不要让文件依赖易失的临时路径。转义所有用户提供的文本，作为文本展示而非可执行 HTML。

页面和左侧导航默认按用户提供的后台顺序：图片与视频 → 分类 → 标题 → 描述 → 变体 → 材料 → Tags → 尺寸；仅展示本次适用字段，价格及其他经营选项按用户要求添加。默认不展示物流、制作背景及其待填占位，也不为模拟完整后台而补齐无关章节；研究依据放最后并可折叠。后台实际顺序变化时随之调整。

- 每个文本字段独立复制，复制内容不含中文说明、字段名称、来源或统计。反馈成功必须来自实际复制成功；失败时允许手动选择复制。
- 个性化模块仅在适用时展示，并按问题类型提供独立复制内容：文本输入和文件上传给标题及适用说明，上传需区分文件时给标签；dropdown 给标题与各选项，不生成说明字段。数据映射及默认不展示的设置见 [字段规则](listing-rules.md)，不将多个问题压成旧单字段。
- Tags展示一条半角逗号连接的整组内容和一个复制按钮，不展示单标签卡片；显示实际项数，未满目标时如实说明。
- 图片按序列出缩略图、文件名、英文 ALT、字符数与复制按钮；有替代版本说明二选一，避免重复上传。
- 选择项给出实际可选值或核对指引；没有证据时不编分类路径或属性选值。
- 尺寸优先采用目标市场常用单位，并保留原单位；数值可单独复制，旁边清楚标单位。区分商品整体与书写区域等适用尺寸，换算后标近似值。
- 已确认、建议待确认、缺失字段可辨识。待填占位符不混入可直接复制的正式文案。

## 单一资料源

`listing-data.json`记录：商品与店铺身份、市场语言币种、事实与来源/确认状态、关键词证据、当前文案及字段分配、图片文件与ALT及文案范围内的未决项。变体、中文编号、尺寸等按商品实际需要记录；价格、库存等经营字段仅在本次确需使用时记录，物流与制作背景不设为必填项，缺失时不进入文案待补清单，不为满足通用结构编造不适用字段；有个性化时按问题类型记录标题和适用的说明、选项或上传标签。偏好及平台约束分开记录来源。

交付引用一个明确的当前版本入口，并分别记录文案、图片视觉确认与平台适用状态。确认、换图或商品范围变化后清理已失效的待办：不能一处写“已确认”，另一处仍要求确认同一事项。成品改为材料包或反向调整时，核对标题、描述、选项、图序与ALT，撤下不再出售内容的购买暗示。历史文件可保留，但不把旧稿和旧包并列标为当前交付。

字段修改时先更新该资料，再生成受影响的HTML、文本和下载包，不重用其他商品事实。输出路径稳定，保存后检查文件存在；更新前保留可恢复版本，已存在的用户另行编辑内容保留，不能用早期脚本覆盖后续修改。

最终稿的图片、缩略图和ALT对应同一组实际已验收文件；新图必须查看，不根据策划表猜画面。已有查看记录且文件未变时可沿用，不因只改标题或Tags重新审全部图片。更换图片后更新受影响的引用与ALT；图片缺失时不标为最终稿。

## 完成检查

机械检查可用短脚本，避免让模型凭目测数长度：
- 按[已核实的字段约束](listing-rules.md)检查实际复制文本的长度、必填性、类型和字符合法性，包含空格/标点/换行；计数显示当前值及适用上限，dropdown 不因没有说明而报缺失。变体按本次核实的字段限制，不能套用个性化或旧任务的数字。
- Tags检查实际项数及相关性；目标未满要说明，不把无关标签补满视作验证通过。标题在长度范围内也须复核清晰度与商品事实。
- 按[搜索意图覆盖检查](listing-rules.md#搜索意图覆盖检查)核对核心用途、属性、收礼对象、礼物意义与赠送/使用场景，记录实际采用字段或缺失理由；同时回查用户已确认的标题详略、语言及排除项，防止局部优化撤销其他偏好。
- 标签组内完全/近似重复、跨字段短语重合分别检查；当前店主已确认互补偏好时评估新增覆盖，重复提示不等于删除所有共用单词。
- 图序、文件、ALT 一一对应；编号、中文、英文含义、价格在图稿、描述、变体间一致。旧图没更新则标为待替换，不能谎报完成。
- 文案既覆盖相关搜索意图，也能让买家快速理解核心购买理由、商品区别与选择方式；不以字符数用满或关键词数量替代质量判断。
- 核对实际使用的单位换算、币种及售价；仅在用户要求时检查价格测算，缺费用不报净利润，未确认库存不编数量。默认不检查或追问物流时效与制作背景。
- 所有复制按钮指向唯一有效字段；链接与资源可用。可用浏览器时检查桌面/窄屏排版、实际复制内容；未实际验证的能力如实说明。
- 生成下载包时解包检查HTML、资料源及当前文案一致，图片清单与实际包内容一致；不以磁盘文件已更新推断旧压缩包也已更新。
- 没有新要求或新证据时沿用已确认字段。与现有同店商品作语义对比，而非为了不同强行更换准确品类词。

交付时提供 HTML 链接，简要列出真实待补项。只有影响最终使用的缺口才追问；不以“再确认一次”阻止已经授权的修改。
