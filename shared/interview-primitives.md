# 访谈与输入收集原语（深挖式 / 清点式）

向**店主**提问收集信息的交互原语，唯一真源（#119）。四份基座访谈脚本（`shop-foundation/references/interview-*.md`）与各 skill 的输入清单只引用本文件，不复述原语正文；各自保留自己的维度 / 字段内容。不覆盖客服场景（向买家发消息归 orders-customers 客服 SOP，买家不是信息源而是服务对象）。

## 风格判据

| 风格 | 用当产出是… | 当前消费方 |
|---|---|---|
| **深挖式**（启发式） | 原则 / 策略 / 价值观——没有标准答案，靠追问显影 | BRAND.md / BRAND_MARKETING.md / MARKETING_PLATFORM.md 基座访谈 |
| **清点式**（盘点式） | 事实 / 必填字段——有标准答案，缺的补齐即可 | SHOP.md 事实档案访谈；listing-catalog 输入清单、pinterest-autopin 输入清单、image-synth 盘点输入 |

选错风格的信号：对事实字段做「你期待的是什么感觉」式追问（应清点），或对价值观只做填表不追问反例（应深挖）。

## 共享不变量（两种风格都必须）

1. **避免诱导**：不把猜测塞进问题（如「你的品牌是不是高端路线？」），保持开放。
2. **不替用户原创**：品牌身份语言、店铺介绍 / 公告原文、退换货等法律承诺必须店主亲笔，agent 只记录；没写就 TODO。
3. **宁缺毋滥**：答不上 → `_TODO（待沉淀 / 待补）_ — {{内容}}（{{原因}}）`，不硬填、不编造；TODO 留给后续真实任务回头沉淀。
4. **回放确认**：每维度（深挖式）/ 每块（清点式）结束回放「我听到 / 记录的是…」，**暴露取舍**（会写 X、不写 Y、避免 Z），冲突列出让店主选、不替店主拍板；校准后再继续。
5. **开场预告**：先一句话说清当前在哪个维度 / 块、打算问什么大方向（深挖式），或接下来过几个块、大约多久（清点式）。

## 深挖式细则

- **单问单答**：同一轮输出只放一个明确问句；不用「先搞清楚三个问题」、编号清单或连续问号开场。缺多块信息时先问最容易回答的一个，等店主开口后再按缺口追问下一块。
- **office-hours 节奏**：每维度一个主问题 → 按回答挑 1-2 个追问（具体例子 / 反面边界 / 取舍原因），不一次抛完整问题清单。参考的是 office-hours 的节奏，不照搬其产品诊断内容。
- **具象优先**：问题落在可感的例子和场景上，不问抽象定义。
- **提问节制**：每维度最多一轮主问题 + 两轮追问；用户仍答得浅时不硬挖，标 TODO 收兵。
- **推进感**：每轮说明这个回答会决定文档里的哪一段，用户才知道自己在帮什么定型。

## 清点式细则

- **缺必填一次性问全**：先盘点已给输入，缺必填项停下来集中问，不要边做边追问。
- **可一轮多字段**：相关字段可以串起来一轮问，节奏比深挖式快。
- **拿不准留空集中确认**：不在单个字段上反复纠缠，最后用一段集中确认。
- **块级回放**：每过完一个块，一句话回放「我记录的是…」并标出 TODO；不追价值观。
- **只核对字段与来源**：事实只核对字段值和出处，不把事实强行抽象成原则。
- **可选项缺失不停下**：基于已有信息推进（如按产品图推测），在草稿里标注哪部分是推测、请店主确认要不要补。

## TODO 占位统一写法

```markdown
_TODO（待沉淀 / 待补）_ — {{尚未明确的内容}}（{{原因}}）
```

写法细节（放哪个文件、模板注释）见各消费方自己的模板说明。
