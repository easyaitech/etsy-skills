# Etsy 专业流程接入协议

适用于 `etsy-product-definition`、`etsy-listing-images`、`etsy-listing-builder`。专业流程来自多轮验证的本地技能；源文件 SHA-256 见 [引入记录](etsy-skills-origin.json)。项目副本独立维护，不运行时读取个人目录、不自动同步本地更新。此协议仅适配 Hermes、店铺数据与交付，不重写技能中的方法和确认节点。

## 任务范围与交接

完整新品上架任务：产品定义确认 → 图片方案确认 → 主图制作及确认 → 按已授权方式完成其余图与验收 → 最终上架填写稿。沿用已经确认的版本和范围，不重复询问。仅定义、仅修图或仅改文案时在请求范围结束；已有定位、调研包或最终图片直接接入，不强制重做。调研默认先交任务书等待用户回传，只有明确授权才自行研究，不自动派发代理。

沿用三个技能已有的 Markdown/HTML、图片计划或交接清单、`listing-data.json`；不新增图库 schema 或业务表。记录商品及 Listing/变体范围、上游路径/版本、确认范围和未决项。图片最终清单必须指向实际验收版本；换图同步文件引用、缩略图、ALT 和受影响文案，不以计划冒充成图。最终 ALT 必须逐图实际查看。

## 工作区与资料

先通过 `ecommerce-stack workspace` 解析当前租户工作区；失败按共享引导处理，不猜个人 HOME。交付目录在该工作区下按商品/任务区分，源稿和 HTML 同版本，旧版本保留，不覆盖用户另行编辑内容。

- 有 BRAND / SHOP / 品牌营销资料时读取并引用。没有基座仍可从已有商品资料开始，不强制初始化。只补问影响当前阶段的必要信息；关键字段缺失时交付待补样稿，不称可直接发布。
- 商品/SKU 事实通过 `listing-catalog` 读取。目录未配置时可以使用用户材料，注明来源，不能声称已查表；线上 Listing 的事实必须走现有只读工具契约。
- 店铺政策来自已确认资料；不编造处理时间、运费、库存、售后或售价。策略建议不等于经营事实。当前用户选择可调整本次表达，但不自动修改品牌基座。商品事实冲突只核对受影响项，不无声覆盖。
- 本地技能中的默认语言/写作偏好继续按其可覆盖规则使用，不提升为不可覆盖的平台规定。平台要求、经验、交付标准与用户偏好分别注明；图片和文案规则分别读新技能的官方来源参考，不套用旧礼赠公式。

## Hermes 图像工具

生图/编辑用当前 profile 真正提供的 `image_generate`；看原图和 QA 使用实际可用的看图能力（如 `vision_analyze`）。模型、后端、凭据、额度由平台管理，skill 不持 key、不选服务商。运行前读取实际工具 schema，核验参考图、编辑、文件输出和多图限制，不能猜参数。画幅参数严格使用 schema 枚举；若只接受 `landscape / square / portrait`，不得传 `3:4` 或 `4:3` 等数字比例（当前 Hermes 会将非法值默认为 landscape）。具体构图比例写进提示词，并核对回执，不以提示词替代真实尺寸检查。

必须将原始商品素材作为实际图像输入，注明每张参考图角色；不得降级为只有文字 anchor，不默默截掉关键参考图。只有工具实际支持时才使用本地文件或签名链接；过期链接重新取，不能要求用户反复重传已经可取的素材。已生成图只是视觉参考，不能替代原始身份真源。

**请求参数不是交付证据**：返回后对照请求质量/尺寸、`reported_quality` / `reported_size`（工具提供时）与实际解码文件。`success=true` 只表示生成成功，不代表达到验收标准。出现回执不符时标明原生规格与质量限制，不声称高质量/指定尺寸已兑现，不重复空跑同一参数。只能在已经授权的范围内按图片技能执行普通等比例导出并记录缩放方式；插值不恢复真实细节，也不把 low 回执改称 high。保真、文字或表达失败仍须修图或停在草稿，不能靠放大绕过。

看图模型的判断是待核对证据：将“原件已有文字/印章”“用户授权新增叠字”“模型擅加内容”分开对照。原件红印与书法本有重叠时保持原件，不能为了消除看图告警改动商品；当前授权文字不能误记为额外文字。真实保真差异仍必须标出。

工具缺失、参考图容量不足或编辑不支持时，保留未完成状态，说明具体缺口；可继续不依赖该能力的策划。不假称已经处理图片，不自动换供应商。额度/后端错误如实报告，不无限重试。真实能力需在 Hermes 实机验证，静态检查不构成运行验收。

## 文件交付与正式入库

按共享引导的专业流程例外，在授权任务内生成、更新本次交付文件，无需逐文件写盘审批；定位与图片确认节点不因此省略。

1. 完成技能要求的文件与视觉检查。AI 图交付副本按图片技能的清理流程处理，即使不入库/不发布也执行；记录哈希和结果，处理后复检，失败版本不作为最终图库。
2. HTML 保持离线可打开：图片嵌入或与资源目录完整打包，不能依赖主机临时路径。批量图片包必须检查包内文件与清单一致。
3. 使用现有 `upload_to_drive --folder 输出 --file <绝对路径>` 上传本店铺交付物；已有明确商品归档目录时可用后端登记的对应目录。使用当前租户注入的配置，不另索 token、不跨店铺。
4. 只有上传回执 `ok=true` 才返回其中的 `url` 并说已上传；失败保留本地文件并说明未交付成功，不把主机路径作为店主可用链接。单文件超过上传工具上限时按文件拆分交付，或拆成各自可用的包；不通过缩小最终图片降低交付标准。HTML 及其资源若无法在限制内交付，报告明确限制，不返回失效包。
5. 用运行环境支持的聊天发图能力展示最终图片预览；预览与下载引用同版本。环境不支持时说明预览未完成，仍提供已上传的实际文件链接，不谎称已展示。
6. 云空间文件交付不等于正式登记 `Assets 素材池`，视觉确认也不等于 Base 写入授权。只有相应入库范围已经获准，才交 `assets-library` B2；列出字段，沿用已有明确授权，不重复审批。将来源角色、版本和清理记录一并传递。未正式入库不阻塞填写稿。

## 商品目录同步

`etsy-listing-builder` 是上架文案生成与修改入口；`listing-catalog` 继续拥有目录、线上读取与原分析入口。最终填写稿先交付。已确认且明确授权写入的字段交 catalog 同步 Base，建议价、未知值和未确认草稿不覆盖正式数据。同步失败如实说明，仍交付已完成文件；实际成功后才报告已写入并附 Base 链接。文案确认不自动授权所有经营字段写入，内部更新和填写稿完成均不代表 Etsy 已发布。
