# 模式 A0：自动起草

冷启动时不要让用户从零回答访谈问题——先从店铺**真实数据**起草一版基座文件，让用户做校正题而不是问答题。灵感来自 product-marketing 类 skill 的「auto-draft from codebase」：起草 → 纠错 → 补漏，比逐项访谈快一个数量级。

## 数据源清单

按「先工具、再粘贴、最后才访谈」的顺序收集。一次收集，四份文件共用。

| 数据 | 获取方式 | 喂给 |
|---|---|---|
| 在售 listing（标题 / 描述 / tag / 价格 / 品类） | `etsy_listings_get` | BRAND 文案语调与定位线索；BRAND_MARKETING 场景与人群线索；SHOP 主营品类 / 价位 |
| 店铺 About / 政策页 / Announcement / Greeting | 用户**粘贴线上原文**（无工具可拉） | SHOP.md 第 2/3/4 段（原文备份，照抄不改写） |
| 买家评价原话 | 用户粘贴或截图 | BRAND_MARKETING 人群 / 触点线索；BRAND 价值主张的买家视角证据 |
| 客服往来消息 | `etsy_customer_messages_get` | BRAND_MARKETING 人群与异议线索；SHOP 政策实际执行口径 |
| 店铺流量 / 转化概况 | `get_etsy_stats`（可 `summarize_etsy_stats`） | BRAND_MARKETING 场景与人群优先级的旁证 |
| 现有社媒账号内容 | 用户提供链接 / 截图 | MARKETING_PLATFORM 现状盘点（已在哪些平台、什么风格） |
| 工作区已有材料（旧文档、笔记） | 直接读工作区 | 四份按内容归位 |

拿不到的数据源直接跳过，不要卡住等；跳过会导致的空白按下面的规则留 TODO。

## 起草规则

1. **事实照抄，推断标注**。从真实数据抄来的内容（政策原文、价位、品类、在售平台）是事实，直接写。从数据**归纳**出的内容（"你的语调偏温和克制""P1 人群像是送礼的丈夫"）是推断——在草稿里对应行标 `⚠️ 推断`，未经用户确认不得去掉标记。
2. **主观维度不硬编**。品牌原则、人群取舍、红线清单这类纯主观内容，数据推不出来就留 `_TODO（待沉淀）_`，不要编一条看起来合理的凑数。TODO 后续走模式 A 针对性访谈或模式 B 沉淀补齐。
3. **按正式模板渲染**（`assets/*_template.md`），不要发明草稿专用格式——草稿确认后就是正式文件，中间不再转换。
4. **一次起草的范围量力而行**：数据足够就四份一起草；数据只够 SHOP + BRAND 就先草这两份，剩下的等前置文件确认后再草（依赖顺序：BRAND → BRAND_MARKETING → MARKETING_PLATFORM；SHOP 独立）。

## 校正循环

1. 整篇展示草稿（一次一份文件，从 SHOP 或 BRAND 开始）。
2. 只问一个问题：「**哪里不对？缺什么？**」不要按段落逐一确认把用户拖入马拉松。
3. 用户每轮反馈后：改草稿 → 重新展示改动段 → 直到用户说可以。
4. `⚠️ 推断` 标记的行必须得到用户明确认可（或修正）才能去掉标记；用户没提到的推断行，在收尾时集中问一次：「这几条是我从数据里猜的，对吗？」
5. 剩余 TODO 逐条报给用户：现在访谈补齐（转模式 A），还是留着以后沉淀。
